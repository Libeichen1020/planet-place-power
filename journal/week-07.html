From a table to a map

The question

Where do U.S. export products go, and how do the scale and distribution of national trade data shape our understanding of economic activity across different places?

The data

The export table comes from the Atlas of Economic Complexity, produced by the Growth Lab at Harvard University. I used the United States’ 2024 goods exports by destination, based on UN Comtrade data and classified using HS92. The values are reported in current U.S. dollars. The table contains 221 destination rows and includes the country names, exports_usd, and export_share. The Usage and Citation statement says that the Atlas is a freely available public resource and that reuse and adaptation are encouraged when users appropriately cite the Atlas and its underlying data sources. The files were based on Comtrade data last retrieved on December 15, 2025.

The boundary layer comes from Natural Earth’s Admin 0 – Countries, 1:110m, version 5.1.1 dataset. It contains 177 country polygons. Natural Earth describes this dataset as public domain, meaning that it can be reused, adapted, and republished without requesting permission or paying a licence fee. The boundary file represents de facto boundaries according to who controls the territory, so the polygons reflect a particular cartographic and political choice.

The method

I first cleaned the Atlas export table before uploading it to ArcGIS Online. I added a new column called iso3, which stores a three-letter country code for each corresponding country. I uploaded the CSV as a nonspatial table by selecting Location settings → None. This was important because the table contains country-level values but does not contain coordinates or its own geometry. I uploaded the Natural Earth boundary file as a hosted feature layer. The boundary layer was the target layer because it contained the country polygons that would remain in the final map. I then created a joined view layer by adding the U.S. export table to the Natural Earth boundary layer. The join matched the ISO_A3_EH field in the Natural Earth boundary layer with the iso3 field in the export table. I used iso codes rather than country names because iso codes provide more straightforward and stable identifiers. Country names can differ between datasets because of spelling, political naming conventions, or long and short forms. The relationship was set to one-to-one, since each destination country should have one row in the export table. I selected a left join, which preserved every polygon in the Natural Earth layer, including polygons without a matching export record. After creating the joined view, I audited the result rather than assuming that the map was complete. I filtered the joined attribute table for records where exports_usd was blank and ADMIN was not blank. These records represent Natural Earth polygons that did not find a matching U.S. export row. A blank value does not mean that the country had no trade; it means that the join did not attach a value from the table. Subsequently, I styled the exports_usd field using Counts and Amounts (Color) to create the choropleth. I also added a separate point layer containing three selected major port cities, which are New York City, Los Angeles and Chicago. The joined layer shows national export values by destination, while the point layer shows transport locations. Comparing them makes the difference between national statistical scale and physical place visible. Finally, I then created a separate CSV point file with three records: the Port of Los Angeles, the Port of Houston, and the Port of New York and New Jersey. The file contains the fields name, latitude, and longitude. The coordinates were obtained from Google Maps and checked against the ArcGIS basemap after uploading the file. Each record included a name, latitude, and longitude. I added this file to ArcGIS Online through Add → Add layer from file and selected Latitude and longitude as the location type. ArcGIS Online converted the coordinates into point features and displayed them on top of the joined boundary layer.
